# Attachments

Paths like `app/...` and `tests/...` are inside `backend/`.

## Attachments

**Attachments** (revision 4 PR 1; `app/files/attachments.py`, `app/files/extract.py`, `app/files/extract_worker.py`, `app/api/attachments.py`): `POST /sessions/{id}/attachments?name=` takes the raw file as the body (no multipart), streamed to `HUB_ATTACHMENTS_DIR/<session id>/<12-hex id>/<safe name>` (default `%LOCALAPPDATA%\MultiAgentHub\attachments`, plain `mkdir`, deleted with the session) within a per-kind cap (`SIZE_CAPS`: image 20 MB, PDF 32, Word/Excel 25, CSV 10, text/code 5), checked by extension (`classify`) and magic bytes (`check_content`); `.hub-attachment.json` beside it holds the metadata and a `sent` flag (`DELETE` discards only unsent uploads; the UI uploads at Send and discards on failure; `sweep_unsent` at startup removes unsent ones older than 24 h). Stored originals and text copies are **read-only** (Claude edits without asking and has the folder through `--add-dir`) and originals get a `Zone.Identifier` stream (ZoneId=3) so Office opens them in Protected View; `remove_tree` clears the flag, retries once and logs anything left. Names lose commas. PDF, Word, Excel (`.xlsx` openpyxl `read_only`, computed values with the formula text where none is stored; `.xls` xlrd) and CSV get a text copy `<name>.txt` (`make_text_copy`, at most 2 at once): the worker runs as `python -I app/files/extract_worker.py` (or `hub-backend.exe --extract-worker` in the bundle, dispatched in `hub_backend.py`). **The worker caps itself** (`extract_worker.cap_memory`): after reading its request and before parsing it puts its own process in a new job object (512 MB committed, 1 process), failing closed (`RLIMIT_AS` elsewhere). A cap from the hub alone isn't enough: in a venv `python.exe` is a launcher, and the interpreter child can start before the hub assigns its job (QA reproduced an uncapped 900 MB allocation and a docx bomb); the hub's job (`WindowsJob`, 2 processes, kill on close) stays for cleanup and the 60 s timeout. Unmocked tests (`test_worker_cap_holds_in_the_process_that_parses`, a docx bomb) check it. At most 2M characters go to a `.part` file renamed only on success; any failure leaves no copy and a `note`, never a failed upload. `POST /messages` takes `attachments: [ids]` (text may then be empty); the `user_message` payload gets `attachments: [{id, name, mime, size, path, text_path, kind, pages, note}]`; files can't go with a command the hub answers or runs off-turn (`_takes_attachments`, 400). `start_task`/`send_reply` take `attachments=`; `with_files` appends the shared "## Attached files" list (paths, text copies, which came natively). Claude: `user_line` puts images and PDFs as base64 content blocks after the text block while the **request's** running totals stay within 100 PDF pages and 32 MB base64 (`claude_blocks`; a PDF needs a known page count; an image counts at most 5 MB since Claude Code downsizes it); the rest go by path and text copy. Earlier turns' blocks aren't counted (live, Haiku 5.5: two 60-page PDFs in one request, and a second one on `--resume`, were both accepted; history is re-sent, so it costs tokens). `--add-dir` the session folder (only once it exists). Codex: `--image <path>` per image, placed right after `--json` so a flag always follows: `exec --image` is greedy (clap `num_args(1..)`) and would take the prompt's `-` as an image; fake Codex parses it the same way. Local: a `vision` model gets this turn's images as base64 `images` (history keeps only `hub_images` paths; `_with_images` strips them), else a `NOTICE` (`no_vision`); text copies and text files are inlined (`INLINE_CHARS`, then `fit()`); the folder is a `LocalTools` read root. No shrunk copies are made: both CLIs downsize large images themselves (21 MB PNG checked live). Handoff: `build_brief`/`messages_brief` list the session's files (`session_attachments`), and `recent_images` (newest 5 from the last 3 messages with files) go with the new agent's first message, in `_handoff` or, after a `wait` switch, with the next `send`. `GET .../{aid}/file` serves images and PDFs as themselves, text/CSV and text copies as `text/plain`, the rest as downloads (`nosniff`); `POST .../{aid}/open` opens with the file's app (`os.startfile`) or, for code and scripts (`openable`), shows it in Explorer; tests pass `create_app(attachments_dir=, open_file=)`. UI: `frontend/src/attachments.ts` (`sendWithFiles`, `useAttachmentUrl` loads images through `apiFetch` as blob URLs, so the Tauri CSP allows `blob:`), `components/Attachments.tsx` (chips, inline images, file rows); `Composer` has the paperclip, paste and a window-wide drop target (Tauri's `dragDropEnabled` is off so HTML drops work).
