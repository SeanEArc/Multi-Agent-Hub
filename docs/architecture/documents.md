# Documents: hub-doc, outputs and Office

Paths like `app/...` and `tests/...` are inside `backend/`.

## Documents

**Documents** (revision 4 PR 2; `app/doctool/` is the `hub-doc` program, `app/documents.py`, `app/outputs.py`, `app/office.py`, `app/api/outputs.py`, `app/api/office.py`): the session folder is now named by the id as stored (`uuid.hex`; a dashed folder from PR 1 builds is kept by `session_dir`), with `outputs/` beside the attachments (`OutputsStore`), made before every turn by `Orchestrator._equip`, which also sets `adapter.documents = DocumentAccess(outputs, bin_dir, office)` (an `AgentAdapter` attribute, set before `start_task` because Codex builds its args eagerly). Claude: `--allowedTools "Bash(hub-doc *)" "PowerShell(hub-doc *)"` (the only pre-approved tool; only the bare name matches) and the outputs folder through the attachments `--add-dir`; Codex: `-c sandbox_workspace_write.writable_roots=["<outputs>"]` (JSON-quoted, valid TOML; **outputs only, never the session folder**: the sandbox could then clear an original's read-only flag) on `exec`, `exec resume` and `server_config`, not summaries; local: `LocalTools(write_roots=)` and `run_command` env. Every agent's env gets `HUB_DOC_OUTPUTS` and the bin folder first on PATH, and its instructions (`DocumentAccess.instructions`, Office commands only when Office was found). `hub-doc` is `[project.scripts] hub-doc = "app.doctool.cli:main"`, copied by `prepare_bin` from the venv's Scripts into `HUB_TOOLS_BIN` (default `%LOCALAPPDATA%\MultiAgentHub\bin`, so the venv's `python.exe` never shadows the user's); in the bundle it is a second exe (`hub_doc.py`, `hub-backend.spec`) beside `hub-backend.exe`, sharing `_internal`, and that folder is used. Contract: one JSON object on stdout, exit 0 ok / 1 refused / 2 failed; `xlsx check|read|edit|render|csv`, `docx read|report|edit|diff|pages|compare`, `pdf pages`. `cli.py` is a supervising parent that never opens a document: it checks every write (`outputs.OutputsFolder.target`: inside `HUB_DOC_OUTPUTS` after `realpath`, so junctions are followed; never an input, a read-only file or a folder; an existing writable name is **overwritten**, the coordinator's decision), stages files in `outputs/.~hub-doc-<hex>/` and moves them only on success, and runs the work in a child (`worker.py`, `python -I -m app.doctool --hub-doc-child`, or the exe itself) that caps itself first with PR 1's `cap_memory` (2 GB; `HUB_DOC_MEMORY_LIMIT` can only lower it), because BetterOffice **aborts the process** on a failed allocation with no Python exception; the parent reports "too large". Excel (`xlsx.py`, `betteroffice-xlsx` 0.2.2): always `recalculate()` first; errors are a cell walk over each sheet's used range (`ErrorCode` values); edit lists changed cells (before/after value and formula) and errors left; `.xls` goes through xlrd into an openpyxl-built `.xlsx` (formulas lost, edits saved as `.xlsx`); no pandas or numpy (with numpy, openpyxl loads OpenBLAS, ~750 MB, and breaks the 512 MB extract worker; `test_pandas_isnt_shipped`). Word: `docx_report.py` pairs BetterOffice's structure export (headings, lists, links, tracked changes) with python-docx (run fonts and sizes, spacing, alignment, styles with inherited sizes and theme fonts) by order, else by text, and lists `issues` (fake heading, direct formatting, direct spacing, empty paragraphs, heading skip, tracked changes); `docx_edit.py` replaces inside runs (the first run keeps its formatting) and refuses a paragraph with a link, field or tracked change (searched in the XML text, `wordxml.py`, since python-docx can't see `w:ins`) or a run holding a picture or mark; `diff` compares accepted-view paragraph text. `pdf_pages.py`: pypdfium2 at 1.5x, PNG written with zlib (no Pillow). Office (`doctool/office.py`, `scripts/office.ps1`, no pywin32): `OfficeRun` runs a PowerShell COM script with a time limit, then `cleanup` kills only **new** WINWORD/EXCEL/POWERPNT processes whose command line has `-Embedding`/`/Automation`, after up to 3 s to exit (`winproc.py` reads command lines with `NtQueryInformationProcess`, no PowerShell); Compare sets the author with `RevisedAuthor`. **One Office run at a time on the PC** (`doctool/office_registry.py`): every run, in hub-doc and in the hub's check, holds a lock file (`msvcrt.locking`, released by Windows if the process dies) from its `before` snapshot through cleanup, so overlapping runs never kill each other's Word; the wait counts against the run's own time limit (then `{ok: false, busy: true}`). While its script runs, a run writes the Office PIDs that appeared (with creation times) to `run-<pid>-<token>.json`; the next run (inside the lock) and every Office check `reap` processes listed by runs whose owner is gone, only if PID and creation time still match and the process is still automation-started Office, so a hub-doc killed by Stop or a Bash timeout doesn't leave Word running. Folder: `HUB_OFFICE_REGISTRY`, default `%TEMP%\MultiAgentHub-office` (writable inside Codex's sandbox, unlike the hub's data folder; conftest uses a temp folder). `DocumentAccess.env` passes the backend's resolved folder to every agent, so all hub-doc runs share the hub's lock whatever their own `TEMP`; an unusable folder fails closed (`lock_folder: true`, Office not started), and a busy or lock-folder answer never says Office is unlicensed. `cancel()` is honored before the script starts and on every poll. **hub-doc reads only `HUB_DOC_READ_ROOTS`** (set by `_equip`: the session's attachments folder, its outputs and the adapter's `cwd`; unset with no `HUB_DOC_OUTPUTS` either, i.e. hub-doc run by hand, means any file; unset under the hub, with `HUB_DOC_OUTPUTS` set, means only the outputs folder's parent, the session folder, so an agent can't widen reads by unsetting it; set but empty or relative-only means nothing): inputs outside are refused (exit 1) before their existence is checked, using `doctool/paths.py` (`real` strips `\\?\`, resolves junctions, short names and `..`; `within` also compares each existing parent by file identity with `os.path.samefile`, which catches an admin-share spelling); inputs are then used by their resolved name (an 8.3 name cuts `.xlsx` to `.XLS`). Save as… uses the same `within` against the attachments folder. The Excel walk is sparse: `export_structured` by row bands (split when cut short at 16 MB), only filled cells, in 20,000-cell bands (100,000-cell bands held ~450 MB more), with a 1,000,000-cell walk limit as a time guard (`truncated` past it). Memory stays lean: `check` streams and keeps only error cells, `csv` writes rows as they come, `edit` keeps only formula cells, error constants and the `--set` targets and reads them again one by one after recalculating. Measured under the 2 GB cap: 1M cells peak about 1.1 GB, about 18 s; 1.5M cells about 1.5-1.7 GB, about 25 s, `truncated`; BetterOffice's own open is about 0.95 GB per million cells, so roughly 2M cells is the remaining ceiling ("too large"). `OfficeDetector` (`app/office.py`) runs the test conversion at startup in a daemon thread and on `POST /api/office/check` (joins a running one; `GET /api/office` → `{status: found|not found|checking, version, ...}`); `HUB_OFFICE_CHECK=false` turns it off (conftest does, except with `HUB_LIVE_OFFICE=1`), tests pass `create_app(office_command=, office_timeout=, tools_bin=)`. Outputs routes: `GET /sessions/{id}/outputs`, `POST .../outputs/open {name}` (Mark of the Web first; scripts and `.xlsm` only revealed, `openable_name`), `POST .../outputs/save {name, destination}` (a full path; never inside the attachments folder). `_consume` compares the outputs folder before the turn, at each `TOOL_RESULT` and at the turn's end, and saves what changed as `output_files: [{name, size, modified, change: created|edited}]` on that event (`outputs.changes`). UI: `OutputFiles.tsx` is a list in the right side panel (under Files changed in Split; a files-only panel in the Panel layout; hidden under 960 px and while previewing) and `ChatOutputs` cards in the transcript where files were written (`outputs.ts` `outputChanges`, which places files no event names by mtime) (Open, Save as… with the existing `FolderPicker`: the shell has no dialog plugin), Settings' **Microsoft Office** line. Tests: `test_documents_acceptance*.py`, `test_doctool.py`, `test_documents_hub.py`, `test_documents_hardening.py`, and one file per fix area: `test_documents_office.py` (lock, registry, lock folder), `test_documents_read_limits.py`, `test_documents_excel_walk.py`; real Office in `test_office_live.py` (`HUB_LIVE_OFFICE=1`).
