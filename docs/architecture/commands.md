# Agent slash commands

Paths like `app/...` and `tests/...` are inside `backend/`.

## Agent commands

**Agent commands** (`app/commands.py`, revision 4: commands for all three agents built; attachments PR 1 and PR 2 built, see Attachments and Documents): `route(agent, text, capabilities)` returns a `Route` (`notice`, `hub`, or `agent` with `local`/`adapter`/`prompt`) for a `/name` message. A `local` command (no model request) still runs once the stint's limit is known reached. Claude: every name in its recorded `init` `slash_commands` (less `terminal_slash_commands`, `__*`, `hub:*` and `CLAUDE_HIDDEN`: clear, model, effort, fast, rename, which get a `NOTICE` pointing at the hub's control and send nothing) is sent as typed, never behind a brief (`Orchestrator._command_events`): with a conversation, `send_reply`; before one, `CLAUDE_LOCAL` (context, usage, cost) run as `ClaudeAdapter.run_command` (`--no-session-persistence`, the parser drops the session id) and others start the conversation with the waiting brief after the command, as its arguments. `/compact` with no conversation yet gets a `NOTICE`. `TurnParser` turns `compact_boundary` into a `NOTICE` with `reason: "compacted"`, `trigger` manual/auto, `pre_tokens`/`post_tokens`, shown as a dashed divider; the UI says "Compacting…" while a `/compact` turn runs. `menu()` lists `CORE_COMMANDS` (compact, context, usage, code-review) first, then hub commands, skills, library skills, then Claude's other commands (`CLAUDE_FALLBACK` before any `init` was recorded). Fake Claude answers `/compact` like 2.1.323. Codex (`CODEX_COMMANDS`; `codex exec` runs none of its slash commands): `server` ones (compact, context, usage, code-review/review, status, mcp) go to `CodexAdapter.run_command` → `app/adapters/codex_commands.py`, which talks to `codex app-server` through `app/adapters/codex_server.py` (`AppServer`: JSON-RPC over stdio via the Runner's new keep-open `RunningProcess.write`; replies by id, notifications queued, Codex's own requests refused; `FORBIDDEN` = `account/read`, never called) with the turn's settings as `-c` overrides (`server_config`). `/compact` = `thread/resume` (`excludeTurns`) then `thread/compact/start`, waiting for `turn/completed`; its `NOTICE` has only `pre_tokens` (the `tokenUsage` after resume; the compaction's own usage isn't the new size). `/context` = that `tokenUsage` (`last.totalTokens` of `modelContextWindow`; none after a review turn). `/usage` = `account/rateLimits/read` (`accountId` dropped), also emitted as a `RATE_LIMIT` (`rate_limit_event_from`). `/code-review` = `review/start` inline on the thread (target uncommitted changes, `baseBranch` = the worktree's `base_commit` via `adapter.review_base`, set by `Orchestrator.send`, or `custom` with the focus text); before a thread it uses an ephemeral `thread/start`, so the native id and waiting brief stay. Review items map to `Shell` rows and the final `agentMessage`. `run_command` puts the app-server process in `_proc`, so Stop kills it; a limit message becomes `LIMIT_REACHED`. `/init` = a turn with `INIT_PROMPT`; `/diff` = `Orchestrator._answer_in_hub` (git status and diff against the worktree base, as a message, no turn or status change); `CODEX_HIDDEN` (clear, new, model, fast, rename, skills) get a `NOTICE`. Fake Codex has an `app-server` mode (exits 9 on `account/read`). Verified live with codex-cli 0.164.0 (`test_commands_through_the_app_server`). Local model (`LOCAL_COMMANDS`, all the hub's own; menu kind `hub`): `compact`, `context` and `usage` go to `OllamaAdapter.run_command` → `app/adapters/local_commands.py`. `/compact [focus]` sends the saved conversation, rendered as plain text (tool calls and results clipped, the whole cut to `prompt_budget` with `_keep_ends`), to the model in a one-off request without tools (`COMPACT_SYSTEM`: task, done so far, current state, next steps, details), then replaces the saved file with one user message (`SUMMARY_HEADER` + summary + "Keep in focus"); if the model fails or answers empty, `adapter.compact_fallback` (set by `Orchestrator.send` to `_compact_brief`: `build_brief(compact=True)`) is used instead. Its `NOTICE` has estimated `pre_tokens`/`post_tokens` (`context_tokens`: system prompt, tool definitions, messages), `summary` and `by` model/hub; the transcript's compacted row shows **View summary**. `/context` reports that estimate against `num_ctx` (and the reply's reserve), `/usage` says there are no limits; both work before a conversation and save nothing. `/code-review [focus]` is a `review` route: `Orchestrator._review_request` takes `git_state` (against the worktree base) and `review_prompt` builds the turn's prompt (`LOCAL_REVIEW_PROMPT`, the diff capped at 20k, untracked files listed); a clean tree or a folder outside git gets a `NOTICE`. Verified live with Ollama (`test_compact_keeps_what_matters`).
