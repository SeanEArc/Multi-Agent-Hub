# Skills

Paths like `app/...` and `tests/...` are inside `backend/`.

## Skills

**Skills** (`app/skills.py`, `app/api/skills.py`, revision 3): a skill is a folder with a `SKILL.md` (YAML frontmatter `name`, `description`), the format both CLIs load. The hub library lives in `HUB_SKILLS_DIR` (default `%LOCALAPPDATA%\MultiAgentHub\skills`): `library.json` (per skill: `source` link/copy, `path`, a switch per agent, `origin` when it lives in a CLI's own folder, `repo`/`commit`/`subpath` for git), `library/<name>` (copies from git or zip), `views/claude` (a Claude plugin named `hub` whose `skills/` are **junctions** to the skills on for Claude; rebuilt on every change; never delete through a junction, `_remove_link` uses `rmdir`), `staging/<id>` (downloads waiting for review, kept an hour). Folders on this PC (including the user's own Claude or Codex skills) are linked, git and zip are copied; `read_skill` suggests switches (off for other agents when a skill names one CLI's tools, off for Local when it has scripts). Delivery: Claude `--plugin-dir views/claude` (skills show as `hub:<name>`); Codex `developer_instructions` += `library.instructions()` (name, description, absolute `SKILL.md` path; Codex reads it with a shell command, as it does its own skills); local model the same list in its system prompt plus `LocalTools.read_roots` (read, never write). An agent isn't given a library skill from its own folder (`origin`). `Orchestrator.send` runs `expand_command` on the prompt only (the transcript keeps what was typed): a library skill becomes `/hub:name` for Claude and the skill's body plus folder in front of the request for Codex and the local model; a Codex skill of its own becomes `$name`. The `/` menu (`GET /api/skills/commands`, `menu()`): Claude's own skills from the `init` stream event, recorded after every turn under the `agent_capabilities` setting (`TurnParser` adds `capabilities` to `STARTED`, the orchestrator pops it before saving), or with none yet from `probe_claude`, a run of `/context` that makes no model request; Codex's from `codex app-server` `skills/list` (JSON-RPC over stdio, 30 s cache, never reads `auth.json`); plus library skills on for the agent and each agent's commands (see Agent commands; `/compact` only for an open session). Older sessions may hold a `handoff` event with `command: "compact"` from the hub's earlier `/compact` (a fresh conversation from the hub's brief); the transcript still shows it as "Conversation compacted". There is no `/clear`: the user decided it is redundant in the hub (a new chat does the same). Before the first message it saves a `NOTICE` instead. Imports never run anything: `clone` is `git clone --depth 1 --no-recurse-submodules` with hooks off; `extract_zip` refuses paths outside its folder and archives over 50 MB. Windows note: a folder made by `tempfile.mkdtemp` (Python 3.13+) is owner-only, which Codex's sandbox can't read, so the library and staging use plain `mkdir`. Tests: `create_app(skills_dir=, claude_home=, discover_native=False)`; `conftest` also sets `HUB_SKILLS_DIR` to a temp folder. Frontend: `SkillsDialog.tsx` (Skills button in the sidebar), `SlashMenu.tsx` in `Composer` (`loadCommands`, `commandsKey`), and `usedSkill` labels Skill tool calls and `SKILL.md` reads as "Used skill" rows.
