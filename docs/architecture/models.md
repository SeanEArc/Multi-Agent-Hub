# Model lists and reasoning effort

Paths like `app/...` and `tests/...` are inside `backend/`.

## Model lists

**Model lists** (`app/model_list.py`, `app/api/models.py`): `GET /api/models` (`ModelCatalog`) gives every picker Claude's current full names (`version`, `CLAUDE_VERSIONS`, update with releases; the aliases are left out as redundant) and Codex's models from `$CODEX_HOME/models_cache.json` (`account`; only its `models` entries, never `auth.json` or `identity`; `CODEX_FALLBACK` when unreadable), each with `available` true/false/null and `efforts`/`default_effort` (Claude: all five; Codex: per model from the cache's `supported_reasoning_levels`, limited to `CODEX_EFFORTS` low/medium/high/xhigh, shown as Light, Medium, High, Extra high (user's decision; max and ultra left out); `agent_effort` turns a max into xhigh for Codex wherever a stint gets an effort). Availability is stored in the `settings` table under `model_availability` (not part of `HubSettings`): `Orchestrator._learn_model` records it after each turn of a stint with a chosen model (before the status is set; false only when the error matches `UNAVAILABLE_MODEL`), and `POST /api/models/check` (`Orchestrator.check_models`) sends each model a tiny `summarize` call in an empty temp folder (4 at a time, limits and other errors are "unknown", never "refused"). `create_app(codex_home=)` keeps tests off the real `~/.codex`; fake Claude has a `badmodel` mode. Frontend: `useModelCatalog()` in `ModelSelect.tsx` shares one copy between pickers (offline fallback `MODELS`), with optgroups, disabled "(not on your plan)" options and **Other…**. The composer's `ModelPicker` (`ComposerControls.tsx`, beside Send, logos in `AgentLogo.tsx`) is one box with a three-column menu: provider, model, effort.
