# Frontend: styling and preview pane

## Styling

Theme: a System/Light/Dark switch in Settings: `theme.ts` sets `data-theme` on `<html>`, and the light tokens live under `:root[data-theme="light"]`. Markdown is `MarkdownText` with `remark-gfm` and `rehype-highlight`, token colors as `--hl-*` theme variables. Agent colors: `--agent-claude/codex/ollama` theme tokens; an `agent-<kind>` class (`agentClass` in `AgentBadge.tsx`) sets `--agent` for everything inside it, so style agent-tinted parts with `var(--agent)`, not `--accent`.

## Preview pane

**Preview pane** (revision 4 PR 3; `frontend/src/preview.ts`, `components/PreviewPane.tsx`, `components/preview/`): clicking an attachment row or image (`Attachments.tsx`, `useOpen`) or **Preview** on an output (`OutputFiles.tsx`) puts a `PreviewTarget` in `PreviewContext` (provided by `SessionView`); the pane sits beside `session-main` (hides the split layout's aside; covers the chat under 900 px). Bytes come as Blobs through `apiFetch` (`useApiBlob`/`useObjectUrl` in `attachments.ts`), never `src=` to the API. Engines are lazy chunks (`React.lazy`), unmounted (worker/WASM released) on close or file switch: `PdfView` (pdf.js 6.5, worker bundled via `?url`; a placeholder per page and an `IntersectionObserver` that draws pages near the view and releases far ones (canvas zeroed, `page.cleanup()`), `task.destroy()` on unmount; `cMapUrl`/`standardFontDataUrl`/`wasmUrl`/`iccUrl` point at `/pdfjs/`, which the `pdfjsAssets` plugin in `vite.config.ts` serves in dev and emits at build, QuickJS left out), `DocxView` (`@betteroffice/docx-react`: `readOnly`, `mode="viewing"`, no toolbar/outline, `initialZoom` fit to the pane and `setZoom` on resize (`ResizeObserver`), `colorMode` from `useResolvedTheme` (`theme.ts`), tracked changes via our own `renderCard` with no Accept/Reject; module init calls `setGoogleFontsEnabled(false)` and `configureDefaultFonts({ fonts })` from the bundled `@betteroffice/fonts`), `XlsxView` (`@betteroffice/xlsx-react` `readOnly`, no toolbar; `hasCharts` looks for `xl/charts/chart` in the zip's central directory and shows **Open in Excel**, since charts draw blank). Size limits from `PreviewTarget.size`: text is fetched only up to 4 MB (`useApiBlob(path, maxBytes)` sends a Range request), other viewers refuse files over 64 MB. `engineFor`: `.xls` and unknown types (and any engine error, caught by `Catch` or `onError`) fall back to the text copy plus **Open**. Reload on overwrite: `PreviewTarget.version` includes an output's size and mtime; `SessionView` (its `useOutputList` refetches when a turn or tool ends) replaces the target when they change, and the pane is keyed by it. Backend: `GET /sessions/{id}/outputs/file?name=` (`OutputsStore.file`, `file_response` shared with the attachments route, `Cache-Control: no-store`, `ACTIVE_SUFFIXES` html/svg/xml always a download). Links: the shell builds the main window itself (`create: false` in `tauri.conf.json`) with `on_navigation` (only `tauri://`, `tauri.localhost` and, in dev, the dev URL) and `on_new_window` (always denied); any other http/https/mailto URL is posted to `POST /api/links/open` (`app/api/links.py`: those schemes only, no control characters, spaces or `"<>`; opened through `app.state.open_file`). Markdown links get `target="_blank"`; the pane also catches `a[href]` clicks and shows a refused link's error. Tauri CSP adds `script-src 'self' 'wasm-unsafe-eval'` and `font-src blob:`; the asset protocol types `.wasm` by content (`application/wasm`).
